# Проект по Linux, М265323

РЕД ОС 8.0.3 без графики (Server Minimal), виртуальная машина, второй диск sdb на 2 ГБ. Редакция обычная, не сертифицированная.

Сеть настраивалась при установке, адрес по DHCP. Имя хоста mephi-2026.domain.local, пинг лежит в ping.out.

После `dnf update` поставил nginx и libcap-ng-utils. tcpdump скачан через `dnf download` в /tmp и установлен через rpm, поэтому в dnf.out его нет.

На sdb один раздел, ext4 с меткой MEPHI_WEB. В fstab он прописан по метке.

nginx включён в автозагрузку, корень сайта /mephi-web. Сначала отдавал 403: файлы были с меткой unlabeled_t. Помогли `semanage fcontext` с httpd_sys_content_t и `restorecon`, сам SELinux не выключался.

Каталог /data/mephi-2026 принадлежит группе mephi (в ней user1, user2, user3), стоит SGID и ACL по умолчанию. Разработчики пишут в файлы друг друга, кураторы только читают, остальным закрыто. umask на это не влияет, проверял с 077. С копированием нюанс: cp берёт права исходного файла, поэтому после него нужен `chmod g+rw`, либо копировать через `cat файл > новый`. Оба варианта проверил. mv тоже оставляет старые права, им в каталог лучше не переносить. ACL каталога в getfacl.out.

set-UID у tcpdump не было, без прав user1 получал отказ. Добавил cap_net_raw и cap_net_admin, после этого от user1 работает.

Кураторам закрыт вход с консоли через pam_access: строка в access.conf и подключение модуля в pam-login (это /etc/pam.d/login). Проверял на tty2, куратора не пускает (отказ в pam_access.out), user1 и root входят. nologin не ставил, чтобы не закрыть вообще всё.

Срок пароля 90 дней задан в login.defs, для root отдельно через chage, минимум 12 символов в pwquality.conf.

После перезагрузки всё осталось на месте. nginx.conf тоже приложил.
